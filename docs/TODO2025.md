Непреклонни правила

❌ Не трий/мести HTML съдържание, текстове, секции, маршрути.

❌ Не променяй UI/UX (размери, цветове, layout, copy).

❌ Не добавяй/махай зависимости без PR бележка.

✅ Всичко е обратимо: един PR, малки комити, описание на всяка промяна.

✅ Включи feature flags/env за всичко ново (пример: NEXT_PUBLIC_FLAG_PPR=1).

🎯 Краен таргет (мобилно): Perf ≥90, LCP ≤2.5s, INP ≤200ms, CLS ≤0.05, TTFB ≤0.5s.

1) Работен процес (за да не счупиш нищо)

Създай branch: perf/safe-optimizations.

Пусни базови измервания (пред/след): PSI mobile, Vercel Speed Insights, bundle analyzer.

Прилагай стъпките по‑долу поетапно (P0 → P1). След всяка стъпка:

локален build ✅

визуален регресионен оглед (сравни UI) ✅

метрики (LCP/TBT/JS size) ✅

Ако има UI отклонение → revert последния комит.

Един фин PR с чеклист (виж §6).

2) P0 — безопасни оптимизации „без промяна на изгледа“
2.1 Server Components по подразбиране

Провери компонентите за ненужен use client.

Ако компонент няма state/effects/handlers → махни use client.

Не пипаш JSX/стайлинг – само директивата.

2.2 Lazy за тежки client части (без визуални промени)

Всички тежки интерактиви под фолда през next/dynamic({ ssr:false }).

Пример (без смяна на UI):

// вместо директен import
const Testimonials = dynamic(() => import('@/components/TestimonialsCarousel'), { ssr: false });
// мястото в DOM остава същото

2.3 Fonts през next/font (без смяна на шрифт)

Запази същия шрифт/тегла, но зареждай чрез next/font с display:"swap", preload и правилни subsets.

Никакви промени по класове/размери → само начинът на доставка.

2.4 Hero LCP — само техническа оптимизация

Остави същото изображение и позиция.

Увери се, че LCP <Image> има priority, коректен sizes, placeholder="blur".

Не сменяш снимки, не променяш стилизация.

2.5 Трети страни — неблокиращо зареждане

GA/Meta/Clarity да минават през next/script със strategy="afterInteractive" или gating след първа интеракция.

Не махай пиксели, не ги мести визуално — само начина на инициализация.

2.6 Кеш и ISR (без промяна на контент)

Страници без runtime данни: export const dynamic = 'force-static'.

С редки промени: export const revalidate = 600;

fetch(..., { next: { revalidate: N, tags:[...] } }) — без да променяш какво се визуализира.

2.7 Конфигурация (без влияния върху UI)
// next.config.js
module.exports = {
  experimental: {
+   reactCompiler: true,
+   ppr: true,
+   optimizePackageImports: ['lucide-react','framer-motion'],
  },
  images: { formats: ['image/avif', 'image/webp'] }
}


reactCompiler/ppr се пазят зад флаг в .env ако е нужно.

Не сменяш runtime/layout.

3) P1 — намаляване на JS без визуални промени

Огледай bundle през ANALYZE=true npm run build.

Големи пакети (framer-motion, embla) → lazy import само на страниците, където вече се ползват.

Икони от lucide-react — импорт само на използваните (не *).

Никакво премахване на функционалности.

4) P2 — като флагове (по избор, off по подразбиране)

Partial Prerendering (PPR shell) само ако не променя изходния HTML редно; включи го с NEXT_PUBLIC_FLAG_PPR.

Virtualization за дълги списъци (TanStack Virtual) — само ако DOM не се пренарежда.

Optimistic UI за форми — без смяна на текстове или layout.

5) Мониторинг и KPI (в рамките на проекта)

След оптимизациите провери: Mobile Perf ≥90, зелени CWV, <3s load — това са целеви KPI в проекта.

Използвай наличните инструменти: @vercel/speed-insights, пиксели/събития и текущия analytics слой (не го променяй като структура).

6) PR чеклист (включи го в описанието)

 Няма промени по UX/копи/лейаут.

 Няма изтрити секции/компоненти/страници.

 Всички промени са обратими и behind‑a‑flag.

 Bundle report приложен (преди/след).

 PSI/Vercel SI скрийншоти (мобилно) преди/след.

 LCP елементът е <Image priority> със sizes и blur.

 Трети страни: next/script / gating след интеракция.

 Static/ISR маркировки добавени, без промяна на съдържанието.

 Няма console errors / hydration warnings.

 Покрити целите от KPI секцията на проекта.
